## 1. Стек (что и почему)

| Слой | Решение | Почему |
|---|---|---|
| CMS | WordPress 6.x + WooCommerce 9.x | согласовано в брифе; Woo даёт готовую модель variable/variation/атрибуты и SEO-экосистему. Headless (Next.js) отвергнут: удваивает сложность, владелец — не разработчик, page-cache даёт ту же скорость |
| Режим | Catalog mode: цены и корзина отключены, кнопка «Запросить КП» | без плагинов-комбайнов — снимаем хуки корзины в теме/mu-plugin |
| Импорт | Собственная WP-CLI команда `wp promen import` (PHP, WC CRUD, батчи) | 47,5 тыс. строк; идемпотентно по SKU, возобновляемо, с отчётом. НЕ WP All Import, НЕ REST API |
| Фильтры | Кастомный AJAX-эндпоинт + tax_query по таксономиям | чипсы из дизайна всё равно требуют своего фронта; meta_query на 18k товаров запрещён брифом; FacetWP платный и не нужен |
| SEO | Yoast + свои шаблоны мета + schema.org (Product, BreadcrumbList) | по брифу |
| Кэш | Redis object cache (уже в проде-плане) + страничный кэш | 18,8k страниц |
| Тема | классическая лёгкая `promen` из design-reference, дизайн-токены в один CSS | перенос 1:1 |

## 3. Таксономии и атрибуты

- `product_cat` — дерево выше.
- Глобальные атрибуты Woo (таксономии, НЕ постмета):
  - `pa_steel` (марка стали) — вариационный;
  - `pa_supervised` (поднадзорность Да/Нет) — вариационный;
  - `pa_dn`, `pa_pn`, `pa_angle` — невариационные, только для фильтров/чипсов.
- Кастомная таксономия `norm` (52 термина из normative_key) — страницы
  нормативов = архивы термина: описание + PDF + список товаров.
  Закрывает пункт брифа «52 страницы нормативов» и даёт перелинковку.
- ~70 колонок `dim_*` — в ОДНО json-мета `_promen_dims` (не 70 постмет!);
  отдельные постметы только для сортировки/вывода: масса, D, s.
- PDF ГОСТов на сайт НЕ выкладываем (решение пользователя 2026-07-17):
  они только источник для написания контента и сверки.

## 3-бис. Модель «серия + типоразмер» (решение 2026-07-19)

Дизайн-карточка (product-otvod-90.html) — страница СЕРИИ (норматив × угол),
а не типоразмера. Поэтому:
- **Серия** `/catalog/sdt/otvody/seriya/gost-17375-2001-90/` — точный вид
  дизайна: H1 «Отвод / крутоизогнутый / 90°», конфигуратор DN ведёт на
  типоразмеры, рендерится медианный товар, canonical на серию (~30 страниц).
- **Типоразмер** (3 120 URL) — тот же шаблон, H1-сплит: серия крупно,
  «820×30 исп. 2 ГОСТ 17375-2001» подстрокой; свой canonical — страница
  самостоятельная, её можно рекламировать и отправлять клиенту.
- Код позиции ОТВ-17375-90 и паспорт-ID ПЭ-ОТВ-17375-90-800 вместо
  машинного SKU (SKU остаётся в конфигураторе и заявке КП).

## 3а. Поведение URL при выборе опций (важно для рекламы и SEO)

- Выбор DN/типоразмера в конфигураторе = переход на ДРУГОЙ товар (свой URL,
  индексируемая страница — на неё можно вести рекламу).
- Выбор стали/поднадзорности (вариация) = тот же путь + query-параметры
  `?steel=09g2s&nadzor=da` через history.replaceState без перезагрузки;
  canonical всегда чистый URL родителя → дублей в индексе нет, а для
  рекламы есть прямые ссылки на конкретную опцию.
- Фильтры-чипсы: `?dn=100&pn=16&gost=17375` на архиве (AJAX), canonical
  на базовый архив.

## 4. Карта перелинковки (главное требование)

1. **Хлебные крошки** на всём: Главная → Каталог → Раздел → Семейство → Товар
   (+ BreadcrumbList schema).
2. **Карточка товара**: таблица типоразмеров (как SPECS в дизайне) =
   ссылки на «братьев» — variable-товары того же семейства+ГОСТа;
   селектор DN в конфигураторе — навигация между ними;
   сталь/поднадзорность — вариации без URL (переключатели).
3. **Карточка → норматив**: блок «Нормативная база» ссылается на страницу
   термина `norm` + прямую ссылку на PDF.
4. **Страница норматива → товары**: архив термина со списком всех товаров
   этого ГОСТа + ссылка на категорию.
5. **Категория → семейства → товары**; чипсы-фильтры (DN, PN, сталь, ГОСТ,
   отрасль) — AJAX, URL с параметрами получают canonical на базовый архив.
6. **Related-блок**: правило по DN — к отводу DN100 предлагаем фланец DN100
   и крепёж для фланцевого соединения (межкатегорийная перелинковка).
7. XML sitemap (товары, категории, нормативы) + пагинация с canonical.

## 5. Импорт: `wp promen import`

- Потоковое чтение CSV, батчи по ~500, флаги `--category=`, `--limit=`,
  `--dry-run`; upsert по SKU (`wc_get_product_id_by_sku`).
- Порядок: variable-родители → их вариации → simple.
- **Дедуп**: в CSV 16 дублей SKU (переходы ГОСТ 17378-2001) — первая строка
  побеждает, дубли в отчёт `scripts/import-report.log`.
- На время импорта: `wp_defer_term_counting(true)`, отключить автосейв
  Yoast-индексации; после — `wc update_product_lookup_tables`,
  пересчёт терминов, сброс кэша.
- Пилот: только отводы (11 325 строк) → отладка карточки и фильтров →
  полный прогон.
