## ЖЁСТКИЕ ПРАВИЛА

1. Не ломать работающие страницы. После КАЖДОЙ правки PHP — `php -l <файл>`.
2. После правок CSS/JS — поднять `PROMEN_VERSION` в `functions.php`
   (сейчас **0.35.7** → ставь следующий).
3. Docker-команды: `docker compose run --rm wpcli <cmd>` из каталога `site/`.
4. Контент — ТОЛЬКО из фактов: `content/aggregates.json`,
   `content/norm_aggregates.json`, тексты ГОСТ из `../normatives/pdf/<категория>/*.pdf`
   через `pdftotext -l 6 файл -`. НЕ выдумывать цифры и свойства.
   **`../normatives/` в репозиторий не входит.** Если папка пуста — значит данные
   на этой машине отсутствуют: не восстанавливай их и не подменяй догадками,
   а останови работу по этому пункту и скажи, что файлы нужно перенести.
5. Инженерный тон, без воды. Как на странице отводов (эталон).
6. Отмечай выполненные пункты `[x]` прямо в этом файле.

### Как проверять страницы

Реестры каталога и нормативной базы **рендерятся на клиенте**. `curl` видит
плейсхолдеры `—` и ноль ссылок на товары даже на полностью исправной странице,
поэтому curl годится только для кода ответа и поиска фаталов:

```bash
curl -s -o /dev/null -w "%{http_code}\n" "http://localhost:8080/<путь>"
```

Наполнение реестра, счётчики и фасеты проверяй браузером с исполнением JS —
иначе рабочая страница читается как пустая.
