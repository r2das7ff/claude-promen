# Переезд prom-en.com на новый сайт — план без потери SEO

Статус: черновик, ожидает подтверждения. Дата: 2026-08-25.

## Исходные данные (снято с живых сайтов 25.08.2026)

| | Старый (prom-en.com) | Новый (prom-en.forgotaboutdre.ru) |
|---|---|---|
| Хостинг | Timeweb, 92.53.96.169 | Timeweb, 92.53.96.132 |
| Движок | WordPress 6.4.10 + Elementor | WordPress + WooCommerce, своя тема |
| Товары | 8 888 URL `/products/<slug>/` | ~15 407 URL `/catalog/<группа>/<кат>/<slug>/` |
| Категории | 1 276 URL `/rubric-products/<slug>/` | `/catalog/...` (product_cat, вложенные) |
| Статика | `/uslugi/`, `/kontakty/`, `/prajs-list-truby/`, `/prajs-list-detali/`, `/trust-us/` | `/production/`, `/contacts/`, `/proekty/*`, `/stati/*`, `/catalog/` |
| Sitemap | `/sitemap.xml`, 10 174 URL, **сгенерирован вручную Netpeak Spider** | `/wp-sitemap.xml`, штатный WP (14 файлов) |

**Главный риск:** структура URL меняется целиком. Ни один товарный и ни один
категорийный адрес не совпадает. Без карты 301 сайт теряет весь накопленный
вес 10 174 страниц и вылетает из индекса на месяцы.

**Второй риск:** тестовый домен `prom-en.forgotaboutdre.ru` открыт для
индексации (robots.txt разрешает всё). Если он уже в индексе — после переезда
получим два одинаковых сайта и склейку не в ту сторону.

## Этап 0. Доступы и замер «до» (1 день)

0.1. **Яндекс.Вебмастер API** — OAuth-токен, скрипт `scripts/seo/wm.sh` готов.
0.2. **Google Search Console** — подтвердить права на prom-en.com.
0.3. **Яндекс.Метрика / Google Analytics** — доступ к счётчику старого сайта,
     выяснить номер счётчика и цели (чтобы перенести на новый сайт **тот же**).
0.4. Снять и положить в `perf-reports/seo-baseline-2026-08-XX/`:
     - ИКС, число страниц в поиске, история индексации за 12 мес;
     - топ-500 запросов (показы, клики, средняя позиция) за 28 дней и за год;
     - топ страниц по трафику (Метрика) — какие URL нельзя терять;
     - внешние ссылки (Вебмастер → «Внешние ссылки») — на какие URL ссылаются;
     - позиции по ключевым запросам (замер до переезда — точка отсчёта).
0.5. **Полный краул старого сайта** своими силами (curl+парсер, sitemap не
     единственный источник): собрать реальные URL, статусы, title, h1,
     canonical, вложенность. Sitemap статичный и мог отстать от сайта.
0.6. Проверить, есть ли `prom-en.forgotaboutdre.ru` в индексе Яндекса и Google.

## Этап 1. Карта редиректов (2–3 дня, основная работа)

1.1. **Категории (1 276 шт.)** — сверяются полуручно: список короткий,
     а вес у них максимальный. Каждой старой рубрике — конкретная новая
     категория `/catalog/...`. Часть старых рубрик в новом сайте стала
     фильтром, а не страницей (например «отводы по градусам», «ППУ по ТУ») —
     для них цель редиректа: категория + предустановленный фильтр в URL.
1.2. **Товары (8 888 шт.)** — автоматом: из slug парсится тип + размер +
     ГОСТ/ТУ (`dnishhe-ellipticheskoe-otbortovannoe-133x8-gost-6533-78`),
     ищется товар в новой базе по тем же полям. Совпадения — в карту,
     несовпадения — в ручной разбор.
1.3. **Непокрытые URL** — редирект на ближайшую категорию (не на главную!).
     На главную вести можно только явный мусор. Товары, которых в новой
     номенклатуре нет вообще, — 301 на категорию, 410 не используем.
1.4. **Правила**: только 301, только один хоп (никаких цепочек), никаких
     редиректов на 404 и на страницы с noindex. Файл карты — в git,
     `content/redirects.csv`, ревью глазами по выборке 100 строк.
1.5. **Реализация**: не .htaccess (10k правил в Apache — заметная просадка на
     каждый запрос), а mu-plugin с хеш-картой (`old_path => new_path`), карта
     компилируется в PHP-массив/`opcache`. Промах — обычная 404 темы.

## Этап 2. Техподготовка нового сайта (параллельно с этапом 1)

2.1. SEO-мета: перенести title/description со старых страниц туда, где новый
     аналог слабее; проверить уникальность на 15 407 товарах.
2.2. Canonical на всех типах страниц, пагинация, сортировки и фильтры —
     в canonical/robots, чтобы не плодить дубли.
2.3. Микроразметка: Organization, BreadcrumbList, Product (без цены — offers
     с `availability`), FAQPage на статьях.
2.4. Служебное в noindex/удалить: `/cart/`, `/checkout/`, `/my-account/`,
     `/sample-page/`, `?add-to-cart=`, теги, автор, поиск.
2.5. robots.txt для боевого домена + `Sitemap:` на `/wp-sitemap.xml`
     (со `lastmod`), Clean-param для фильтров каталога.
2.6. Зеркала: `www` → без `www`, `http` → `https`, слеш в конце — одна
     каноническая форма, все остальные 301 в один хоп.
2.7. Счётчики Метрики/Analytics со старого сайта — на новый, до переключения.
2.8. Страница 404 с поиском по каталогу и ссылками на разделы.
2.9. Скорость: у нас уже есть `PLAN-PERF.md`, добить прод-обвязку
     (fastcgi_cache/Redis) — Core Web Vitals влияют на переиндексацию.

## Этап 3. Переключение (техокно, 1–2 часа)

3.1. Полный бэкап старого сайта: файлы + БД + дамп sitemap и логов доступа
     за 3 месяца (лог нужен, чтобы потом добирать реальные URL с трафиком).
3.2. Бэкап нового сайта (файлы + БД) — точка отката.
3.3. Переключить домен prom-en.com на новый сайт внутри Timeweb.
     WP_HOME/WP_SITEURL, `search-replace` в два прохода (обычный + schemeless,
     см. правила деплоя), SSL-сертификат, редирект на https.
3.4. Залить карту редиректов и проверить **до** снятия заглушки.
3.5. Прогнать все 10 174 старых URL curl'ом: ожидаем `301 → 200`, ноль 404,
     ноль цепочек, ноль редиректов на главную сверх согласованного списка.
3.6. `prom-en.forgotaboutdre.ru` — закрыть: 301 всего домена на prom-en.com
     (или базовая авторизация + noindex, если он остаётся тестовым).

## Этап 4. Первая неделя после переезда

4.1. Вебмастер: новый sitemap, «переобход страниц» на топ-URL, проверка
     раздела «Страницы в поиске → Исключённые» и «Диагностика».
4.2. GSC: sitemap, проверка URL, отчёт «Покрытие».
     Инструмент «Изменение адреса» **не нужен** — домен тот же.
4.3. Ежедневно: 404-ошибки из логов nginx и из Вебмастера → дополняем карту
     редиректов. Это главный источник пропущенных URL.
4.4. Следить за тем, что робот не начал массово выкидывать страницы как
     «дубли» (частая беда WooCommerce-фильтров).

## Этап 5. 2–12 недель

5.1. Еженедельный срез через `wm.sh`: страницы в поиске, показы/клики,
     список просевших URL против baseline.
5.2. Добор редиректов, донаполнение мета, работа с просевшими кластерами.
5.3. Ожидания: временная просадка трафика 10–30% на 2–8 недель — норма при
     полной смене URL. Возврат и рост — при корректной карте 301.

- Доступы: GSC, Метрика, панель Timeweb (домен), доступ к старому сайту (SSH/FTP).

- Согласование даты техокна.
