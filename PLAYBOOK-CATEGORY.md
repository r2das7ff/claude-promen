# Плейбук: подключение новой категории каталога

> Пошаговая инструкция для Cursor. Подключаем ПО ОДНОЙ категории за раз:
> тройники → переходы → днища → заглушки → фланцы → крепёж.
> Образец и эталон качества — пилот «Отводы» (/catalog/sdt/otvody/).
> Приёмку каждой категории делает Claude по чек-листу в конце.

## ЖЁСТКИЕ ПРАВИЛА (нарушение любого = работа отклоняется целиком)

1. **Существующие файлы read-only.** Запрещено редактировать:
   `taxonomy-product_cat-otvody.php`, `taxonomy-product_cat-sdt.php`,
   `single-product.php`, `archive-product.php`, всё в `parts/` (кроме
   СОЗДАНИЯ новых файлов), `assets/js/*`, `assets/css/base.css`,
   `catalog.css`, `product.css`, `category-sdt.css`, все mu-plugins,
   все файлы в `inc/` — КРОМЕ четырёх разрешённых точечных правок,
   помеченных ниже как [ПРАВКА-1..4]. Никаких «заодно улучшил».
2. **Ни одна секция не удаляется и не упрощается.** Страница категории =
   ровно 10 секций + база знаний с 7 табами, как у отводов. Если чего-то
   не хватает — остановись и напиши, чего не хватает, а не выкидывай блок.
3. **Контент — только из фактических источников** (см. «Источники» ниже).
   Выдумывать цифры, диапазоны, свойства сталей, требования ГОСТ — запрещено.
   Каждое число на странице должно быть выводимо из источника. Если факта
   нет — пиши общо («по согласованию», «по стандарту изготовления»),
   но не изобретай конкретику.
4. **Тон и глубина** — как на странице отводов: инженерно, без воды,
   без маркетинговых восклицаний. Термины — отраслевые (DN, PN, Ру,
   исполнение, НК, ВИК/УЗК, сертификат 3.1, поднадзорность).
5. После правок CSS/JS поднять `PROMEN_VERSION` в functions.php [ПРАВКА-4].
6. Каждый шаг заканчивается своей проверкой. Не идти дальше на красном.

## Источники фактов (все локальные)

| Что нужно | Где взять |
|---|---|
| Счётчики, диапазоны DN/PN, стали, углы по категории/семейству | `content/aggregates.json` |
| То же по каждому нормативу + статус/замены | `content/norm_aggregates.json` |
| Готовая аналитика категории (нормативы, покрытие) | `../normatives/reports/catalog_overview.md`, `catalog_analytics.md` |
| Текст стандартов (область применения, типы, требования) | `pdftotext -l 6 "../normatives/pdf/<категория>/<ГОСТ>.pdf" -` |
| Эталон структуры и тона всех блоков | страница отводов + её шаблон `taxonomy-product_cat-otvody.php`, `parts/kb-otvody.php` |
| Слаги фильтров ГОСТ (для ссылок ?gost=) | транслит normative_key: `ГОСТ 17376-2001` → `gost-17376-2001` |

## Шаги (на примере тройников; для другой категории подставить свои значения)

### 1. Импорт данных
```bash
cd site
docker compose run --rm wpcli promen import --category=тройники
docker compose run --rm wpcli promen verify --category=тройники --sample=30
```
✔ verify N/N; счётчик товаров вырос на число позиций категории.

### 2. Роутинг [ПРАВКА-1]
`inc/catalog-filters.php` → `promen_section_landing_slugs()`:
добавить `'troyniki'` в массив. Больше в файле НИЧЕГО не менять.

### 3. Сайдбар каталога [ПРАВКА-2]
`woocommerce/archive-product.php`, блок `.sbn-children`: пункт «Тройники»
из `<div class="sbn-child sbn-child--soon">` превратить в `<a class="sbn-child">`
по образцу пункта «Отводы» (href = get_term_link термина, счётчик = число
позиций из aggregates). Остальные пункты не трогать.

### 4. Шаблон страницы категории (НОВЫЙ файл)
```bash
cp woocommerce/taxonomy-product_cat-otvody.php woocommerce/taxonomy-product_cat-troyniki.php
```
В копии адаптировать ПОД ТРОЙНИКИ (структуру не менять!):
- шапка-комментарий файла; `$otv` → термин `troyniki`; `$otv_url` →
  `add_query_arg('group','troyniki',$shop_url)`;
- **hero**: H1 (3 строки, средняя в `<em>`), описание 2–3 предложения
  (семейства, нормативы, диапазоны — из aggregates), 3 hero-параметра,
  2 HUD-блока (диапазоны + нормативный статус категории);
- **s01 Реестр исполнений**: группы по типоисполнениям категории
  (тройники: равнопроходные/переходные/с опорой/сварные ТЭС — по
  norm_aggregates), в заголовке группы: код, название, подпись,
  диапазон DN, счётчик; строки серий со ссылками
  `?group=troyniki&gost=<слаг>`;
- **s02 Карта типоисполнений**: 4 блока `mg` с реальными счётчиками
  и нормативами; сетка `repeat(4,1fr)` (или 3, если типов 3);
- **s03 Подбор**: 4–5 задач «задача → исполнение → что передать» +
  ссылка `sg-link` на реестр с фильтром у каждой; последняя задача —
  нестандарт → `#request`;
- **s04–s08, s09 Порядок заказа**: тексты универсальные — оставить,
  заменив упоминания «отводов» на семейство категории там, где есть;
- **s10 База знаний**: НОВЫЙ partial (шаг 5).

### 5. База знаний категории (НОВЫЙ файл `parts/kb-troyniki.php`)
Структура — копия `parts/kb-otvody.php`: 7 табов
(01 Виды, 02 Параметры подбора, 03 Нормативная база, 04 Материалы,
05 Документация, 06 Как заказать, 07 Доставка и оплата).
- Таб 07 «Доставка и оплата» копируется БЕЗ изменений.
- Табы 01–03 — экспертный контент по категории: классификация типов
  с их нормативами и DN-диапазонами (из norm_aggregates + текст ГОСТ
  через pdftotext), сравнение типов таблицей, параметры подбора
  (какие размеры задают изделие — для тройников: D×s магистрали,
  d×s ответвления, равнопроходность), нормативная база со статусами.
- Табы 04–06 — адаптация отводных (стали — из aggregates категории).
В шаблоне категории заменить include kb-otvody на kb-troyniki.

### 6. Проверка URL-матрицы
```bash
for u in "catalog/sdt/troyniki/" "catalog/?group=troyniki"; do curl -s -o /dev/null -w "$u → %{http_code}\n" "http://localhost:8080/$u"; done
# + карточка товара и серия из verify-выборки → 200
```

### 7. Самопроверка контента (обязательно, письменно в отчёте)
- [ ] Все числа на странице сверены с aggregates/norm_aggregates (перечислить)
- [ ] Ни одного упоминания «отвод» в текстах тройников
- [ ] 10 секций + 7 табов КБ на месте (посчитать и написать)
- [ ] Группы реестра: сумма счётчиков = числу позиций категории
- [ ] Ссылки серий ведут на фильтрованный реестр (проверить 2 руками)
- [ ] Карточка товара категории: плашка типоразмера, конфигуратор,
      серия, модал заявки — работают
