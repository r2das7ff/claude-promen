# Грабли API Яндекс.Директа

Всё проверено вызовами на живом аккаунте в сентябре 2026. Каждый пункт
стоил либо часа отладки, либо неверного ответа заказчику.

## Главное правило: имена полей спрашивать у API

На неверное значение в `FieldNames` Директ отвечает ошибкой 8000 и
**перечисляет все допустимые**:

```python
{"SelectionCriteria": {...}, "FieldNames": ["ZZZ"]}
# → "ожидается одно из значений: AdImageHash, LogoExtensionHash, ...,
#    BusinessId, TrackingPhoneId, PreferVCardOverBusiness, ..."
```

Работает для `TextAdFieldNames`, `TextCampaignFieldNames`,
`UnifiedCampaignFieldNames`, `SelectionCriteria.Types` и прочих.

Угадывать бессмысленно: я перебрал `OrganizationId`, `CalloutIds`,
`PermalinkId`, `DemographicsAdjustment` — ни одного попадания, и на этом
основании заявил заказчику, что возможностей нет. Все они существуют, но
под другими именами.

## Где что лежит

| Возможность | Уровень | Имя поля |
|---|---|---|
| Организация Яндекс Бизнеса | объявление | `BusinessId` |
| Организация по умолчанию | кампания (v501) | `DefaultBusinessId` |
| Данные организации | сервис `businesses` | `Name, Address, Phone, ProfileUrl, CounterId` |
| Уточнения | объявление | запись `AdExtensionIds`, чтение `AdExtensions` |
| Изображение | объявление | `AdImageHash` (сервис `adimages`) |
| Быстрые ссылки | объявление | `SitelinkSetId` (сервис `sitelinks`) |
| Отображаемая ссылка | объявление | `DisplayUrlPath` |
| Номер коллтрекинга | объявление / кампания | `TrackingPhoneId` / `DefaultPhoneId` |
| Возрастная корректировка | `bidmodifiers.add` | `DemographicsAdjustments` — **массив** |
| Мобильная корректировка | `bidmodifiers.add` | `MobileAdjustment` — объект |
| Общие минус-слова | кампания | `NegativeKeywordSharedSetIds` |
| Пакетные стратегии | сервис `strategies` | — |

## Что принимается только при создании

`AdExtensionIds` (уточнения) и `SitelinkSetId` **принимаются в `ads.add`,
но не в `ads.update`** — при обновлении Директ отвечает «неизвестный
параметр». Существующему объявлению их не привязать.

Обход: пересоздать объявления. Порядок безопасный — сначала создать новые,
сверить количество, только потом удалять старые. Для черновиков это ничего
не стоит.

А вот `DisplayUrlPath`, `BusinessId`, `Title`, `Text`, `Href` обновляются
штатно.

## Второй заголовок склеивается

`Title2` при создании через API **всегда** склеивается в `Title`, и при
чтении возвращается `None`. Проверено на коротких и длинных заголовках.
Это поведение комбинаторных объявлений, а не ошибка. Не пытайтесь «чинить»
повторной записью: передав прочитанный `Title` обратно вместе с новым
`Title2`, вы получите двойную склейку («Отводы гнутые. Каталог 3 247
позиций. Челябинский завод»).

## Ошибки не поднимаются наверх

Пакетные методы (`update`, `add`) возвращают HTTP 200 и общий `result`,
а ошибки лежат **внутри** по каждому объекту:

```python
for item in result.get("UpdateResults", []):
    for e in item.get("Errors", []):
        ...
```

Без этой проверки 242 неудачных обновления проходят молча. Обязательно
разбирать `UpdateResults`, `AddResults`, `SuspendResults`, `DeleteResults`.

То же про свой код: если обёртка возвращает пустой список при ошибке
запроса, аудит покажет нули и вы решите, что настройки нет. Падать надо
громко.

## Стратегии старых кампаний не редактируются

Кампании, заведённые до весны 2024, на любую попытку изменить
`BiddingStrategy` или `DailyBudget` отвечают:

```
5005 Поле задано неверно
Невалидное значение: ...CampaignStub{super=...CopyableCampaign{}, id=...}
```

Перебраны: обе версии API, `AverageCpc` с лимитом и без, с `BudgetType`,
вместе с `Name`, `WB_MAXIMUM_CLICKS`. Везде отказ, при этом обновление
одного `Name` проходит. **Перевод на ЕПК не поможет — они уже ЕПК**
(`Type: UNIFIED_CAMPAIGN` в v501). Только интерфейс или пересборка.

## hasSearchVolume возвращает строку

```python
{"Keyword": "отвод ост 24 125 03", "AllDevices": "NO"}
```

`if x.get("AllDevices")` пропускает `"NO"` — непустая строка истинна.
Сравнивать только с `== "YES"`. На этой ошибке чуть не собралась вторая
кампания из мёртвых фраз.

Второе: проверка идёт по написанию фразы. Слаги фасетов латинские
(`ost-24-125-03`), а ищут кириллицей — без перевода получаются фразы
«отвод ost 24 125 03», по которым не придёт никто.

## Минус-слова Директ переписывает

При приёме списка:

* ставит `!` перед служебными словами: `как сделать` → `!как сделать`,
  `б у` → `б !у`;
* меняет дефис на пробел: `18599-2001` → `18599 2001`;
* **схлопывает по лемме**: `косые` исчезает при наличии `косой`, `чертеж`
  — при наличии `чертежи`, `теплицы` — при `теплица`.

Сверка «до/после» покажет это как потерю, хотя минусация работает по всем
формам. В список класть одну форму слова, сверку вести по нормализованной
форме и общему началу.

В общих наборах (`negativekeywordsharedsets`) допустимы только буквы,
цифры и пробелы: `б/у` со слэшем отвергается ошибкой 5002.

**Но схлопывание не безгранично: «бу» и «б у» — разные минус-слова.** Я
выкинул «б у» как дубль «бу», и в первый же день показов прошёл запрос
«трубы б у большого диаметра». Раздельное написание надо минусовать
отдельно (Директ хранит его как `б !у`).

**Стоп-лист нельзя подключать к кампании вслепую.** Директ не
предупреждает, если минус-слово совпадает со словом ключевой фразы, — фраза
просто перестаёт показываться. У PROM-EN общий стоп-лист содержал «прайс»,
а у старых кампаний было 99 и 63 фразы вида «труба … прайс»: подключение
заглушило бы их молча. Перед подключением сверять слова набора с фразами
кампании; при конфликте — новые слова в минус-слова самой кампании.

И перед добавлением минус-слова сверять его с каталогом: «хомут» выглядел
мусором (хомуты для труб), но у завода 12 опор хомутовых.

## Числовая марка стали в ключе — это ещё и диаметр

Генератор «изделие × марка» собрал фразы «труба 20», «отвод 20» из марки
стали 20. При широком соответствии «20» читается и как диаметр 20 мм —
в первый день по такой фразе показалась полимерная труба varmega PE-Xa.
Для числовых марок (20, 10) ключ строить только со словом «сталь»:
«труба сталь 20», «отвод из стали 20».

## Черновик на модерацию отправляется через объявления

Созданная через API кампания лежит в статусе `DRAFT` и **сама на модерацию
не уходит**. Очевидный `campaigns.resume` не подходит:

```
8300 Неверный статус у объекта
Кампания является черновиком и не может быть остановлена
```

`campaigns.moderate` и `adgroups.moderate` не существуют вовсе (ошибка 55).
Работает только **`ads.moderate`** по идентификаторам объявлений — и уже
следом за объявлениями на модерацию уходят группы и вся кампания.

Отправлять стоит при нулевом балансе: проверка идёт бесплатно и занимает
часы, а деньги в это время не тратятся. К моменту пополнения кампании уже
готовы к показам.

## Останавливать надо кампанию, а не объявления в ней

`campaigns.suspend` работает на любых кампаниях, включая старые, у которых
`CampaignStub` не даёт менять стратегию. Ограничение касается только
`BiddingStrategy` и `DailyBudget` — состояние правится штатно.

Я этого не проверил и пошёл длинным путём: погасил 2 515 объявлений в
одиннадцати кампаниях вместо одиннадцати вызовов `campaigns.suspend`.
Разница не только в объёме работы:

* остановка кампании **обратима одной командой** и сохраняет состояние
  объявлений внутри;
* остановка объявлений требует помнить, какие из них были включены, и при
  возврате кампании их придётся включать отдельно.

Разница состояний, которую нужно различать:

| Состояние | Что значит | Запустится при пополнении счёта |
|---|---|---|
| `OFF` | не показывается сейчас, обычно из-за пустого счёта | **да** |
| `SUSPENDED` | остановлено человеком | нет |

Поэтому «выключить кампанию, чтобы не тратила» — это `campaigns.suspend`,
а не ожидание, что она сама не запустится.

## Мелочи, на которых спотыкаешься

* `bidmodifiers.get` требует `Levels` **внутри** `SelectionCriteria`.
* `sitelinks.get` и `vcards.get` требуют явные `Ids` — перечислить всё нельзя.
* Описания быстрых ссылок внутри набора **не должны повторяться** (6000).
* Заголовок быстрой ссылки ≤ 30 символов, описание ≤ 60.
* Ключевая фраза — не более 7 слов (5140).
* Площадки в `ExcludedSites` сравниваются без учёта регистра: два
  написания одного пакета — ошибка 9802 на весь список.
* `PriorityGoals` принимает только `Operation: SET`, и то лишь у
  конверсионных стратегий: при «максимум кликов» — 3500 «Не поддерживается».
* `ExternalId` сегмента Аудиторий в Директе = **2 000 000 000 + id сегмента**.
* `CounterIds` живёт внутри `TextCampaign`/`UnifiedCampaign`, не на верхнем
  уровне кампании.
* Архивные объявления обновлять нельзя (8300) — их надо отфильтровывать.
* `adgroups` и `campaigns` требуют хотя бы один критерий в
  `SelectionCriteria`, иначе 4001.

## Версии API

`v5` и `v501` живут параллельно. `v501` знает ЕПК-структуры
(`UnifiedCampaign`, `DefaultBusinessId`, `AdvertisedItem`), `v5` — нет.
Для чтения ЕПК-полей нужен `v501`, всё остальное одинаково.
